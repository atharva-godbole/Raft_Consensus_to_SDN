5. LOG INSPECTION PROTOCOL (WHEN & HOW)
-------------------------------------------------------------------------------

[A] When to Inspect Logs
-------------------------
* After Node Startup: Verify clean initialization, BoltDB loading, and leader election.
* After Dynamic Joins (/join): Confirm followers establish heartbeat pipelines.
* After Injecting Flows (/flow): Verify log replication and ovs-ofctl execution.
* During Failover: Trace heartbeat timeouts, candidate terms, and datapath reconciliation.
* During Node Recovery: Confirm revived node syncs missing logs and stays a follower.

[B] How to Inspect Logs
-----------------------
1. Real-time follow:
    tail -f node1.log
2. Stream all nodes simultaneously:
    tail -f node1.log node2.log node3.log
3. Filter key lifecycle events:
    grep -E "LEADER|FOLLOWER|COMMIT|RECONCILE|ERROR|FATAL" node2.log
4. Inspect recent entries:
    tail -n 30 node1.log

6. DEAD-TO-ALIVE NODE RECOVERY & CATCH-UP TEST
-------------------------------------------------------------------------------
1. Inject a test rule into surviving leader (Node 2) while Node 1 is offline:
    curl -X POST http://127.0.0.1:8002/flow \
      -H "Content-Type: application/json" \
      -d '{"op":"ADD", "match":"ip,nw_dst=10.0.0.3", "action":"drop", "priority":100}'

2. Revive Node 1 (must use bootstrap=false):
    ./single-raft-sdn -id=node1 -http=127.0.0.1:8001 -raft=127.0.0.1:9001 -data=data/node1 -bootstrap=false > node1.log 2>&1 &

3. Verify log catch-up:
    tail -n 25 node1.log
    curl -s http://127.0.0.1:8001/status

4. Confirm datapath integrity:
    sudo ovs-ofctl -O OpenFlow13 dump-flows s1
    mininet> h1 ping -c 3 h2
