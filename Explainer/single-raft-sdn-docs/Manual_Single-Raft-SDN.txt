===============================================================================
RAFT-BASED FAULT-TOLERANT SDN CONTROLLER: OPERATIONAL MANUAL
===============================================================================
(Note: If running the software on VM, ssh into the VM for stable performance, instead of using the VM's CLI/GUI.)
-------------------------------------------------------------------------------
1. PREREQUISITES & ENVIRONMENT SETUP
-------------------------------------------------------------------------------
Ensure the required toolchains and network packages are installed:

  * Go: Version 1.20+
  * Python: Version 3.12
  * Open vSwitch & Mininet:
      sudo apt-get update
      sudo apt-get install -y openvswitch-switch mininet
  * Or activate python3 -m venv .venv, then activate .venv/bin/activate, then pip install mininet

Ensure Mininet's Python 3 bindings are available in your Python 3.12 environment:
    python3.12 -c "import mininet" || sudo apt-get install -y python3-mininet

Directory Structure:
    ~/raft-sdn/single-raft/
    ├── cluster.go          # Raft engine & BoltDB persistence setup
    ├── fsm.go              # Replicated KV Finite State Machine (Country:Capital)
    ├── main.go             # HTTP API + SDN switch flow updater
    ├── raft_runner.py      # Mininet orchestration + Custom interactive CLI
    └── data/               # Auto-generated runtime data (logs, BoltDB, PIDs); (Note: data is deleted at the beginning of every program execution.)

-------------------------------------------------------------------------------
2. NETWORK & SYSTEM TOPOLOGY
-------------------------------------------------------------------------------
  * Switch: Open vSwitch bridge "s1" (Management IP: 10.0.0.254:6633)
  * Service Virtual IP (VIP): 10.0.0.100:8000 (Transparent external endpoint)
  * Endpoints:
      - n1 (Node 1.1): IP 10.0.0.1 | MAC 00:00:00:00:00:01 | Switch Port 1
      - n2 (Node 1.2): IP 10.0.0.2 | MAC 00:00:00:00:00:02 | Switch Port 2
      - n3 (Node 1.3): IP 10.0.0.3 | MAC 00:00:00:00:00:03 | Switch Port 3
      - h_client:      IP 10.0.0.10| MAC 00:00:00:00:00:10 | Switch Port 4

Data path packet steering:
  The current Raft leader dynamically configures OpenFlow rules on "s1". Traffic
  sent by h_client to 10.0.0.100:8000 is rewritten (Destination NAT) to the 
  active leader's IP and port. Return traffic is rewritten (Source NAT) back to
  10.0.0.100 so the client's TCP stack accepts it transparently.

-------------------------------------------------------------------------------
3. SINGLE-COMMAND EXECUTION WORKFLOW
-------------------------------------------------------------------------------
Launch the complete cluster and network topology with a single command:

    cd ~/raft-sdn/single-raft
    sudo python3 raft_runner.py

The script automatically executes the following startup sequence:
  1. Purges lingering processes and cleans the data/ directory.
  2. Builds the single-raft-sdn Go binary.
  3. Launches the isolated Mininet network namespace topology.
  4. Configures base OpenFlow 1.3 ARP flooding and intra-mesh routing.
  5. Boots n1, n2, and n3 in their respective network namespaces.
  6. Forms Raft quorum by joining n2 and n3 to seed node n1.
  7. Pre-populates baseline application state (France: Paris, Japan: Tokyo).
  8. Drops directly into the custom interactive cluster prompt: raft-sdn>
Note: if the script fails due to "rm: cannot remove 'data/*: Permission denied", run with sudo: sudo python3 raft_runner.py
-------------------------------------------------------------------------------
4. INTERACTIVE CLI COMMAND REFERENCE
-------------------------------------------------------------------------------
Run these commands directly inside the "raft-sdn>" interactive shell:

  * Inspect Cluster Health:
      status            # Shows running state and Raft role for all nodes
      status n1         # Displays status only for node n1

  * Read Application Data (queries VIP 10.0.0.100 via h_client):
      read France
      read Japan

  * Write Application Data (submits to VIP 10.0.0.100 via h_client):
      write Italy Rome
      write Spain Madrid

  * Kill a Specific Node (simulates failure without affecting other nodes):
      kill n1
      kill n2
      kill n3

  * Revive a Failed Node (reboots as follower with -bootstrap=false):
      revive n1
      revive n2
      revive n3

  * Standard Mininet Utilities:
      h_client ping -c 2 10.0.0.1      # Ping test inside host namespace
      sh ovs-ofctl -O OpenFlow13 dump-flows s1  # Inspect switch flow table
      exit                              # Teardown cluster and cleanup

-------------------------------------------------------------------------------
5. LOW-LEVEL MANUAL CHECK COMMANDS (FOR DEBUGGING & DIRECT ACCESS)
-------------------------------------------------------------------------------
If testing outside the custom CLI wrappers, run these lower-level commands 
directly inside the Mininet prompt:

[A] Manual Data Plane Ingress / Egress
  * Direct Write via VIP:
      h_client curl -s -X POST http://10.0.0.100:8000/data \
        -H "Content-Type: application/json" \
        -d '{"country":"Germany","capital":"Berlin"}'

  * Direct Read via VIP:
      h_client curl -s http://10.0.0.100:8000/data?country=Germany

[B] Direct Node Inspection (Bypassing VIP)
  * Read from a specific follower:
      n2 curl -s http://10.0.0.2:8000/data?country=Germany
      n3 curl -s http://10.0.0.3:8000/data?country=Germany

  * Inspect node role, term, and leader address:
      n1 curl -s http://10.0.0.1:8000/status
      n2 curl -s http://10.0.0.2:8000/status

[C] Manual Process Control
  * Safely kill only n1 using its isolated PID file:
      sh kill -9 $(cat data/n1.pid)

  * Revive n1 manually inside its namespace:
      n1 ./single-raft-sdn -id=n1 -node-ip=10.0.0.1 -node-mac=00:00:00:00:00:01 \
        -switch-port=1 -data=data/n1 -bootstrap=false > data/n1.log 2>&1 & echo $! > data/n1.pid

[D] OpenFlow Switch Table Inspection
  * Check active VIP NAT rules:
      sh ovs-ofctl -O OpenFlow13 dump-flows s1 | grep 10.0.0.100

  * Dump full flow table:
      sh ovs-ofctl -O OpenFlow13 dump-flows s1

-------------------------------------------------------------------------------
6. STEP-BY-STEP FAULT TOLERANCE TEST PROCEDURE
-------------------------------------------------------------------------------

Step 1: Check baseline cluster state
    raft-sdn> status
    Result: n1 is leader (is_leader: true), n2 and n3 are followers.

Step 2: Read baseline data through the VIP
    raft-sdn> read France
    Result: {"capital":"Paris","country":"France"}

Step 3: Kill the active leader (n1)
    raft-sdn> kill n1
    Result: [n1] Process killed successfully.

Step 4: Confirm election failover and datapath retraining
    raft-sdn> status
    Result: [n1] is OFF. Either n2 or n3 is promoted to leader.

    Check switch table to verify the new leader retrained OVS:
    raft-sdn> sh ovs-ofctl -O OpenFlow13 dump-flows s1 | grep 10.0.0.100
    Result: Actions point to the port of the newly elected node.

Step 5: Execute writes while the original leader is dead
    raft-sdn> write Canada Ottawa
    raft-sdn> read Canada
    Result: Client request succeeds seamlessly via VIP 10.0.0.100.

Step 6: Revive the dead node and verify catch-up
    raft-sdn> revive n1
    raft-sdn> status n1
    Result: [n1] is running as FOLLOWER and contains the "Canada: Ottawa" key.

-------------------------------------------------------------------------------
7. LOG INSPECTION & CLEAN TEARDOWN
-------------------------------------------------------------------------------

[A] Inspect Logs
All logs and runtime files are strictly localized in ~/raft-sdn/single-raft/data/:
  * Follow real-time output for a node:
      tail -f data/n1.log
  * Check commit operations across all nodes:
      grep "COMMIT" data/*.log
  * Check leader transitions:
      grep "LEADERSHIP" data/*.log

[B] Clean Teardown
  * Normal Exit: Type "exit" in the raft-sdn> prompt.
  * Manual Emergency Teardown (if processes hang):
      sudo pkill -9 -f single-raft-sdn
      sudo mn -c
      rm -rf data/
